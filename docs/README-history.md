# 我们一家

多用户家庭共享记录软件。一个网址全家人共用：**万年历待办**、**图文动态（家庭朋友圈）**、**重点事项记录本**、**家庭记账**。

除成员显式设为「仅自己可见」的内容外，软件内所有信息默认对全家同步展示。

## 本次更新（v4.25.0）

五项：**截图识别从 30 多秒降到几秒**（瓶颈归因 + 五个手段）、**推送方式里标明哪条通道真的能用**、
**AI 识别参数精简掉四个**、**待办 / 内容 / 记账三类各自配推送渠道**、**企业微信配置页去掉一句文档指引**。
一句话概括：AI 识别不再「点完去泡杯茶」，推送设置不再「选完才发现发不出去」。

### 需求 1：AI 识别提速（30 多秒 → 几秒）

先把 30 秒拆开看，四条各有各的解法（缺一条就只快一点点）：

| 瓶颈 | 为什么慢 | 本次怎么改 |
| --- | --- | --- |
| ① 模型侧「思考」 | qwen3-vl / o 系列默认开思考，一次识别先吐几百个思考 token 才出结果，实测占掉一半以上时间 | 一律关思考：百炼端点发 `enable_thinking:false`，OpenAI 官方发 `reasoning_effort:"minimal"`，其它 OpenAI 兼容层发 `"none"` |
| ② 上传体积 | 长边 1280 + JPEG 0.75 + 上限 900KB，转 base64 后约 1.2MB；家用宽带上行只有几 Mbps，光上传就要十几秒 | 长边降到 1024、质量 0.7、上限 480KB（base64 后约 640KB），识别精度实测无明显影响 |
| ③ 参数不兼容导致整图重发 | `temperature` / `max_tokens` 对推理型模型（o1/gpt-5/reasoner）非法 → 上游 400 → 剥参数后**整张图再传一遍** | 推理型模型**根本不发**这两个参数（`REASONING_MODEL_RE`），一次成功，省掉一整趟往返 |
| ④ 同一张图反复识别 | 改分类、误触重传，都要重新等一遍 | 进程内缓存：`sha1(模型 + 图片)` 为键，10 分钟内直接复用模型原文，上限 12 条 |

另外两处细节：**慢失败不重试**（超时预算已耗掉一半就不再重试，避免 30 秒变 60 秒）、
提示词里的候选分类条数 12 → 8（输入短一点，首字延迟更低）。

**慢在哪能看见了**：识别结果新增 `timings { totalMs, modelMs, cached }`，进度条显示
「识别完成 · X 秒（模型 Y 秒）」，命中缓存显示「识别完成 · 0.X 秒（缓存命中）」——
以后再觉得慢，先看是模型慢还是网络慢。

> 取舍说明：关掉思考后，极模糊的截图分类准确率可能略降。提示词里的分类提示与「自动 / 严格」两种分类模式都保留，
> 严格模式下识别不出会要求你手选，不会瞎记。

### 需求 2：推送方式区分「已启用 / 未启用」

- 「我的 → 推送方式」六个选项后面直接带状态：`（已启用）` 或 `（未启用：具体原因）`。
  原因分得清：`「邮件推送」总开关关着` / `还没配发件邮箱` / `企业微信应用未启用` / `还没配飞书群机器人`。
  成员看不到家庭设置时显示「未启用（原因，由管理员配置）」，不猜。
- 弹窗顶部多一块汇总：**已启用**：企业微信、邮件 —— **未启用**：飞书群、钉钉群。
- 数据来源：`GET /api/me` 新增 `push_channels`（mail / wecom / feishu / dingtalk 四条 `{enabled, ready}`），
  **成员也拿得到** —— 没有为此放宽 `/api/settings` 的管理员边界。
- 未启用的通道仍然可以先选上：管理员配好后自动生效，不用回来重选。

### 需求 3：AI 识别参数删掉四个

- 界面删掉**思考模式 / 思考预算 / 最大输出 / 采样温度**四个控件（设置区从 14 项降到 10 项）。
- 保存接口不再写这四个键；老客户端带上来也**静默忽略、不返回 400**（沿用「先停读、再停校验」口径）。
- 旧库里残留的 `ai_thinking / ai_thinking_budget / ai_max_tokens / ai_temperature` 一律不再读取、也不再回显，
  全部由内部常量接管：`SPEED = { thinking:false, maxTokens:1024, temperature:0 }`。
  识别是「抽取」不是「创作」，温度锁 0、输出 1024 token 足够，不需要暴露给使用者。

### 需求 4：待办 / 内容 / 记账三类各自的推送渠道

- 位置：「消息推送设置」下**待办提醒 / 内容通知 / 记账**三个设置弹窗里，各多一个「这一类走哪条通道」下拉，
  默认「沿用全局」。
- 存 `user_prefs.channel_todo / channel_notify / channel_bill`：**空 = 删掉这一行 = 跟随全局**
  （`users.push_channel`）—— 老库零迁移，不配就和以前完全一样。
- 裁决只有一个出口 `push.channelFor(用户, 类别, 偏好表)`：类别偏好优先，没配回落全局；
  投递时优先级是「调用方显式指定 > 类别渠道 > 全局」。
- 记账日报 / 月报按**每个人**自己的 `channel_bill` 投递（企微 / 飞书 / 钉钉群仍按通道去重只发一条）；
  待办提醒与内容通知分别走 `channel_todo` / `channel_notify`，三类互不影响。
- 三个键的取值与 `push.CHANNELS` 严格同源（六个值），非法值 400，不会静默改成默认。

**怎么验证**：九套测试 5728 项全绿（lunar 2438 / migrate 138 / remind 183 / notify 131 / api 516 / bill 447 / e2e 910 / wecom 198 / docker 767）。

**升级提示**：换镜像 / 安装包即可。原先调过的思考模式、思考预算等四项会自动失效（不再读取），
三类推送渠道默认「沿用全局」，不配置就和以前完全一样；想给某一类单独指定，去对应设置弹窗里选一次。

## 上一版（v4.24.0）

三项：**AI 识别改成通用平台接入（不再绑定千问）**、**推送渠道新增飞书群与钉钉群**、
**企业微信「可信 IP」代理**（含中转服务器部署文档）。一句话概括：AI 想接哪家接哪家，推送多两条进群的路，
企业微信不再被家用宽带的可信 IP 卡住。

### 需求 1：AI 识别通用化（OpenAI 兼容端点，不再限定千问）

- 「我的 → AI 参数设置」改成**通用三件套**：接口地址（默认 `https://api.openai.com/v1`）、API Key、模型 ID。
  OpenAI / 智谱 / Gemini 等任何 OpenAI 兼容平台都能填，界面给出跨平台示例模型与价格提示，
  不再有「一键拉取模型列表」「千问专属预设」这些入口。
- **零操作升级**：密钥还留在旧键（`qwen_api_key` 或 `DASHSCOPE_API_KEY` 环境变量）时判定为 legacy，
  接口地址自动回落百炼兼容端点、默认模型回落 `qwen3-vl-flash` —— 升级前后识别行为完全一致，
  界面提示「把三项重新填一遍保存完成迁移」。
- `enable_thinking` / `thinking_budget` 是百炼扩展参数，现在**只在百炼端点发送**（`isDashScope` gating），
  换到其它平台不会因为塞了不认识的参数而 400；参数自愈机制照常兜底。
- 配置来源优先级：settings 新键 → 环境 `AI_API_KEY`/`AI_BASE_URL`/`AI_VL_MODEL` → 旧键 / 旧环境变量（legacy）。
  docker-compose / .env 样例同步加了 `AI_API_KEY` / `AI_BASE_URL` / `AI_VL_MODEL` 兜底通道，
  `DASHSCOPE_API_KEY` 保留为老配置兼容。

### 需求 2：推送渠道新增「飞书群」「钉钉群」

- 管理员在「消息推送设置 → 推送渠道设置」里新增两块配置（`/api/hooks`，管理员专用）：
  群机器人 Webhook + 可选加签密钥 + 保存 / 发测试按钮，外加家庭级开关（`push_feishu_enabled` / `push_dingtalk_enabled`）。
  加签按官方口径：飞书 = HMAC-SHA256 空密钥放 body；钉钉 = base64 后 encodeURIComponent 拼 URL。
- 家人在「推送方式」里多了「飞书群 / 钉钉群」两个选项（`PUSH_CHANNELS` 扩成六值）。
  待办提醒、内容通知、记账日报/月报全走既有投递逻辑。
- **群机器人的语义**：没有「个人绑定」，一次投递全家可见 —— 同一通道多人选择时 push.deliver / sendReports
  都会**按通道去重只发一条**；免打扰复用 mail_outbox（channel 参数化）；`auto` 的语义刻意不扩展
  （不会「我没配飞书却收到飞书消息」）；通道没开 / 没配 Webhook 时逐人明确报错，绝不静默丢。
- 记账报表的「企微失败补邮件」（v4.23.0）语义保持：飞书 / 钉钉腿失败时原因进 errors 与推送日志，但不回邮件 ——
  群消息与邮件是两套送达方式，失败原因在「推送日志」里查。

### 需求 3：企业微信「可信 IP」代理

- 企业微信 API 要求出口 IP 在后台白名单里，家用宽带动态 IP 基本没法玩。现在「企业微信接入设置」弹窗里多了：
  **启用可信 IP 代理**开关 + 代理地址 + 鉴权 Token（留空 = 不修改，GET 永不回传明文）。
- 生效方式：出站基址统一收口在 `apiBaseOf(cfg)` —— 启用代理后取 access_token、发消息、下载媒体三个出站请求
  都改走 `proxyUrl` + 原路径，并带 `X-FH-Proxy-Token` 头；token 缓存 key 含 proxyUrl，切换代理立即生效。
  **回调方向不受影响**（企业微信 → 我们不走代理）。
- 中转服务器部署说明见 `docs/wecom-proxy.md`：原理（URL 改写 + 鉴权头 + 403 拒绝无 token 请求）、
  应用侧四步配置、**方案 A nginx**（含 `proxy_ssl_server_name on`）与**方案 B 零依赖 Node 转发脚本**（含 systemd）
  两种现成配置 + 验证清单 + 安全注意。

**结构变化**：新增 `src/feishu.js` / `src/dingtalk.js` 两个协议模块（零依赖、绝不反向 require 业务层）与
`docs/wecom-proxy.md`；不改任何既有表，无 ALTER，老库启动即用，升级只换镜像 / 安装包。

**怎么验证**：九套测试 5690 项全绿（lunar 2438 / migrate 138 / remind 183 / notify 131 / api 509 / bill 435 / e2e 908 / wecom 198 / docker 750）。

**升级提示**：换镜像即可。原来填过千问密钥的不用动（自动迁移）；想换平台就在「AI 参数设置」里把三件套重填一遍。

## 本次更新（v4.11.0）

本版是**前端视觉重做 + 三套主题**：推翻原来的暖橘单主题，换成一套「设计令牌 + 主题色板」的视觉系统，
提供**青野（绿）/ 米白（奶油）/ 澄蓝**三套配色，每位家人在「我的 → 外观主题」里自选，**选择跟着账号走**
（存 `users.theme`，换设备也一样），首屏按缓存先上色不会闪。桌面端底部导航改为左侧竖排导航栏，

本版是**纯修复**：**零结构变更**（一张表、一个字段都没动），

> **其中第 3、4、7 条有一个共同根因**：v2.0.0 引入的最小重绘里，「握着焦点就跳过」的判定**太粗** ——
> 只要焦点落在某个节点的**子树**里，整棵子树（连同卡片里的新消息、新评论、被删掉的行）就都不更新。
> 而输入框必然住在某张卡片里，所以「点了删除，焦点在删除按钮上」「打完字焦点在输入框里」这两种最常见的
> 情形，都会把整张卡片冻结。修法是共用的一步：**把保护粒度收窄成「只跳焦点那一个节点」**
> （`value` / `checked` 是 DOM 属性，重建节点才会丢，跳输入控件自己就够），
> 再给列表项补 `data-key` 让增删与序号解耦。

| # | 遇到的问题 | 原因（一句话） | 修法 |
|---|---|---|---|
| 1 | 记账：填了百度 OCR 的 API Key / Secret Key，保存却提示「两项均为空，没有需要保存的内容」 | 取值函数只查弹窗里的字段（`#modal-layer`），而这两个输入框在**记账「设置」页**里，根本不在弹窗 → 永远读到空串 | 取值函数改成「**弹窗优先、其次页面本体**」（`fieldValue`），弹窗内与页面内的字段都能读到 |
| 2 | 记账：收入分类下面也挂着「预算」输入框，像是必须填 | 预算那一列的收入、支出**共用同一段模板**，收入列也跟着渲染了输入框 | 预算框**只在支出列渲染**；服务端 `setBudget` 同时拒绝收入分类（绕过界面也塞不进去） |

**逐项细节**

1. **OCR 密钥 / 新增分类读不到输入值（第 1、5 条）**
   - 根因是**一处共用的取值函数**：`modalValue(key)` 只在 `#modal-layer [data-mk=...]` 里找。
     而「记账设置」是页面里的一个**视图**（不是弹窗），密钥与「新增分类」两个输入框都渲染在 `#main` 里 ——
     所以无论用户填什么，读回来永远是空串，于是分别报「两项都空着」与「请先填分类名称」。
   - 修法：新增 `fieldValue()` / `fieldChecked()`，**先弹窗、再页面本体**；
     旧名 `modalValue` / `modalChecked` 保留为薄包装（函数声明，任何位置调用都安全）。
     之所以**弹窗优先**：同名键若两边都有，弹窗里那份才是用户正在编辑的。
   - 顺带：保存密钥成功后清空两个输入框（明文 Secret Key 不该继续停在屏幕上，
     placeholder 会变成「已保存（尾号 xxxx），留空表示不改」）；添加分类成功后也清空。

2. **收入分类不显示、也不要求填预算（第 2 条）**
   - 前端：`catRow(kind)` 按 `kind === 'expense'` 决定是否渲染 `.cm-budget`；
     收入那一列只保留分类 chip 与「添加」，并在提示里写明「收入分类不需要设预算」。
   - 服务端：`setBudget()` 增加校验 —— 传了大于 0 的金额而分类不在**支出**分类里就报 400。
     不校验的话会在 `bill_budgets` 里留下一条**永远不生效**的数据，属于本项目最忌讳的「保存了但没用」。
   - 传 `0`（取消预算）时不校验：用户想清掉一条历史脏数据不该被拦。

3. **删除明细后立刻消失（第 3 条）**
   - 这是**最小重绘**带来的回归。早先整片 `innerHTML` 替换时，列表被整体重建，删掉的自然就没了；
     改成对齐式重绘后，**「握着焦点就跳过」的判定过粗**：它跳过的是「焦点所在的整棵子树」。
     用户点「删除」按钮时，焦点落在这个按钮上 → 而按钮在**整张列表卡片**里 →
     于是 `patchNode` 在卡片这一层就 `return` 了，**卡片里所有行一个都不更新**，屏幕上留着已删的那条。
   - 修法两步：
     ① **收窄保护粒度** —— `holdsFocus(node)` 从「焦点在 `node` 的子树里」改成「焦点**就是** `node`」。
        真正怕被重绘弄丢的只有输入控件自己（`value` / `checked` 是 DOM 属性，重建节点才会丢），
        跳它一个就够；它的兄弟节点该更新照样更新。
     ② 明细行带 `data-key="bill-<id>"`：被删的行在新树里**不存在**，
        于是走到「删除未使用的旧节点」那一步被真正移除 —— 与焦点停在哪儿无关、
        也不会因为「后继行顶替了它的位置」而让内容错位。

4. **发送后清空输入框、聊天记录立刻回显（第 4 条）**
   - **输入框为什么没清空**：`<input>` 的 `value` 改的是 DOM **属性（property）**，
     改不动 `outerHTML`；最小重绘对叶子节点只比 `outerHTML`，于是判定「这个输入框没变化」，
     原样留着刚发出去的那句话。所以必须**显式清空**（搜索框的「清除」按钮早就踩过同一个坑）。
   - **聊天记录为什么像是没更新**：与第 3 条同一个根因 —— 焦点在输入框里，
     输入框是整张记账卡片的后代，卡片被整棵跳过，新气泡画不出来。
     收窄保护粒度后即恢复；气泡再补 `data-key="chat-<id>"`，
     新消息一定是新增节点、不靠序号认领，顺序与增删都稳定。
   - 顺带修掉：清空只发生在「服务端确实回应了」之后 —— 别在请求还没落地时就把用户的话抹掉。

5. **重复金额二次确认（第 6 条）**
   - 判定放在**服务端**（`bills.findRecentDuplicate`）：窗口 120 秒，条件 = 同一个人 + 同方向 + 同金额。
     120 秒足够覆盖「手抖点两下」「网络慢以为没成功又点一次」；
     又不会误拦「早上买菜 30、晚上买水果又 30」这种真实的两笔。
     刻意**不要求分类也相同**：分类是解析器猜的，同金额但分类被猜得不一样时**更**需要问一句。
   - 命中时**先不入库、也不写任何聊天记录**（连用户那句话都不写）：
     否则用户点「取消」之后，聊天窗里会留下一条没有对应账目的气泡，看起来像「记了但没生效」。
   - 前端收到 `needConfirm` 弹一句确认：**取消** → 什么都不发生，输入框保留原话（方便改个数字再发）；
     **确定** → 带 `confirm: true` 重发，这次才真正落库并回显两条气泡。
   - 消息文案带上了上一笔的分类与备注，用户据此判断是不是自己刚才那一下。

6. **发表评论后立刻显示（第 7 条）**
   - 根因与第 3 条同源：**焦点保护跳过的是一整棵子树**。
     评论列表与评论输入框原来同在 `.comments` 里，提交后焦点还在输入框（按 Enter 提交尤其如此），
     于是整层 `.comments` 都不更新 —— 评论要等焦点移开才冒出来。
   - 修法：
     ① 收窄保护粒度（同第 3 条，这条是根治）；
     ② 把评论列表单独包一层 `.comment-list`，与 `.comment-form` **平级** —— 即使将来粒度再被放宽，
        输入框那一层与评论列表也不在同一棵子树里，不会再互相牵连；
     ③ 评论项自身加 `data-key="cmt-<id>"`，删除评论同理立刻生效。

**怎么验证（每一项都有对应断言）**

| # | 验证方式 | 预期结果 |
|---|---|---|
| 1 | 在「记账 → 设置 → 截图识别」填入 AK/SK 后点「保存密钥」，再回服务端读 `/api/bills/settings` | 状态变「已配置」，`hasOcrAk/hasOcrSk` 为真、`ocrAkTail` 是尾 4 位，**密钥本身不回传** |
| 2 | 打开设置页看「收入分类」那一块；再直接向 `/api/bills/budgets` 提交一个收入分类 | 收入块下**预算输入框数为 0** 且写明原因；直接提交返回 **400** |
| 3 | 焦点停在某行的「删除」按钮上（真实浏览器的点击就会这样）再删除该行 | 那一行**立刻消失**、列表条数减一；`[data-key="bill-<id>"]` 元素不复存在 |
| 4 | 焦点留在输入框里发送一句话 | 输入框**立刻为空**；聊天窗立刻出现该笔的系统气泡（带 `data-key`） |
| 5 | 在「支出分类」下输入名字点「添加」 | 新分类出现在列表；输入框自动清空；服务端分类列表里能读到它 |

| 7 | 焦点留在评论输入框里发表评论 | 评论**立刻**出现（`.comment-list` 内条数 +1） |

以上 7 项均有自动化断言守着（`_verify/bill.test.js` 覆盖服务端判定与预算边界，
`_verify/e2e.test.js` 覆盖七项交互）。**特别注意**：这些前端断言必须**显式 `focus()`**，
否则 jsdom 不会移动焦点、断言「碰巧」通过 —— 这正是之前测试全绿、用户却在真机上踩到的原因。

**逐项细节**

1. **同步不整页刷新（输入与播放都不被打断）**
   - 渲染前先比一次**数据指纹**（每个页签一份：待办列表、动态、记录本、记账…）。
     指纹一致 → **直接返回，一个 DOM 字节都不动**，正在播放的视频、正在敲的输入框毫无感觉。
   - 指纹变了也只做**递归最小重绘**：同类型的节点就地更新属性、只增删该增删的孩子；
     **焦点所在的那一个节点跳过**（用户正在这里输入，动了就是灾难）。
     ★ 这里 v2.0.1 修正过一次：原先是「焦点在这棵子树里就整棵跳过」，
     那会把整张卡片（含新消息、新评论、被删掉的行）一起冻结 —— 详见「本次更新（v2.0.1）」。
   - 输入框里有内容的节点，重绘前后按 `data-preserve` 键**原样搬运**，光标与选中范围也还回去。
   - 效果：你在「发帖」里敲到一半，家里的轮询刚好刷新了一次 —— 字还在、光标还在、视频还在放。

2. **视频缩略图（真实首帧，不是黑框）**
   - 只写 `preload="metadata"` 是不够的：Safari 与部分安卓浏览器在没拿到播放指令时**只解元数据、不画任何一帧**，列表里就是一排黑框。
   - 做法：给视频地址追加媒体片段 `#t=0.1`，浏览器会**定位到 0.1 秒并把那一帧画出来**。
     不生成缩略图文件、不改上传流程、不占额外存储。
   - 已经带 `#` 的地址不会重复追加（同一份路径可能被复用）。

3. **图片进全屏后再单击**
   - 旧写法在 `mousedown` 里关灯箱：`mousedown` 一关，灯箱立刻 `visibility:hidden`，
     紧接着浏览器做 **click 的命中测试**，此刻指针下面已经是灯箱底下的那张缩略图 ——
     于是「关闭」的那一下点击顺手又把灯箱打开了，看起来就是「关不掉 / 闪一下又弹回来」。
   - 现在：**关闭挂在 `click` 上**（命中测试发生在隐藏之前，目标就是灯箱自身，不会穿透）；
     单击图片本身**延迟 260ms** 关闭，给双击缩放留出取消窗口；缩放状态下单击是「准备拖动」，不关闭。
   - `mousedown` 只剩一件事：放大之后的拖动查看。原先散在两个 `mousedown` 监听里的逻辑合到了一处。

4. **发帖 / 视图切换 / 搜索合成一张工具栏**
   - 动态页顶部只有**一张卡**：第一行是「动态流 / 按日历看」与「✍️ 发帖」，
     第二行是搜索框，下面是标签筛选 —— 一眼能看出这一页能干什么，也不再是三块各占一行的拼盘。
   - **发布框默认收起**（不占版面）。草稿**存在 `state` 里**而不是只活在 DOM 中，
     所以收起 / 展开 / 切页签都不会丢掉敲了一半的字；收起时「发帖」按钮上会显示**草稿数角标**。

5. **记录本分类去掉「×」**
   - 原因：它和「点一下 = 筛选」直接冲突（手指稍微偏一点就变成删分类），
     而且长相像「这个分类可以有多个 / 能勾选」，误导大于便利。
   - 删除入口只剩**长按（手机）/ 右键（桌面）**，chip 的悬停提示写明「点按筛选 · 长按删除该分类」。

6. **上传进度条**
   - `fetch` 至今没有暴露「上传进度」的标准做法（`ReadableStream` 的 duplex 只在部分浏览器可用，
     且拿不到已发送字节数），所以这次单独开了一条 `XMLHttpRequest` 通道用 `upload.onprogress`，
     其余请求继续走 `fetch`——不为一件小事把整套网络层换掉。
   - 进度条浮在屏幕下方，显示文件名 / 数量、百分比与进度条；**图片、视频、附件**三条上传路径都接上了。
   - 成功显示「完成」，失败显示「N/M 成功」并逐条列出失败原因；**绝不会**留一条永远 99% 的进度条挂在屏幕上。
   - 视频是唯一「大到能看出等待」的一类，进度条在这里价值最大（一条动态最多 3 段、单段默认 50MB）。

7. **个人通知设置（非管理员也能自定义）**
   - 以前这些开关全在**管理员**手上，非管理员只能被动接受。现实是爸爸想每天收待办、不想看动态通知，妈妈正好相反。
   - 现在「**我的 → 通知设置**」对**所有人**可见，两个开关都是**三态**：
     **跟随管理员 / 开启 / 关闭** —— 「没表态」与「明确不要」必须是两件事，
     否则老用户升级后会因为多了一个默认值而被悄悄改变行为。
   - 「通知内容」可只留自己关心的类型（待办 / 动态 / 记录本 / 评论）；两组**免打扰时段**都支持跨零点（如 22:30–06:30）。
   - **只能收窄、不能放大**：管理员把某一类整体关掉之后，个人再打开也收不到 ——
     否则「管理员关掉了通知」这件事就形同虚设。所以页面与弹窗里都**实时显示管理员的当前设置**，
     让你分得清「我关了」和「管理员关了」。
   - 弹窗里那行摘要直接写在「我的」页上（如「开启 · 待办 · 免打扰 22:30–06:30」），不用点进去确认。
   - 刻意**没有**下放「提前 N 天」：那是**每条待办**的属性（全局默认 + 待办自身），
     再叠加个人偏好会出现「同一条待办对不同人不同时刻提醒」，「为什么我没收到」将无法复现。

8. **每周重复 + 「周期提醒」**
   - 待办表单的「重复」现在是六选一：不重复 / **每周** / 每月公历 / 每月农历 / 每年公历 / 每年农历
     （按周期由短到长排列）。
   - **每周** = 按基准日的星期几，每 7 天一次（周是公历概念，没有「农历每周」）。
   - 底部那块卡从「年度重复」改名为「**周期提醒**」：它现在收的是**所有**重复事项（每周 / 每月 / 每年），
     原来那个名字在加了每月、每周之后已经名不副实。
   - 每周事项同样**没有完成状态**（重复事项只有「下一次提醒」），与年度 / 月度规则共用同一份实现
     （`public/repeat.js`，前后端同一文件），不会出现「日历上看得到、提醒却不发」。

9. **家庭记账（新模块，详见「一、功能 → 6. 家庭记账」）**
   - **聊天式一句话记账**：「今天买菜 30 元」「昨天打车 26」「收红包 88.88」「这月工资 12000」——
     服务端解析出**金额 / 收支 / 分类 / 日期**，界面用聊天气泡回显「记了什么、归到哪类」，还能顺手提醒超预算。
   - **截图识别（千问视觉模型）**：上传微信 / 支付宝账单截图，走**服务端代理**的阿里云千问（前端零密钥）。
     识别结果**只打开确认弹窗**，必须用户点「确认记账」才入库 —— 识别错一行字的代价是账目长期不准，不值得为省一次点击去冒。
   - **智能分类**：支出 12 类、收入 7 类；原话里写了分类名时以分类名为准（含管理员自建分类），否则按关键词打分。
   - **统计**：个人 / 家庭 × 日 / 月 四个口径，另有当月支出分类排行。
   - **每日定时推送**：管理员设一个时间点，**每人收到一封**把「个人账单 + 家庭账单」合并起来的邮件
   （v4.2.0 起合并，末尾还附一份「今日待办预告」）；即使当天 0 笔也发（「今天没花钱」本身也是信息）。
   - **OCR 额度预警**：每月免费 1000 次，用到 **950** 就在页顶与聊天窗提示；**跨月自动清零**
     （主键就是月份字符串，天然跨月归零，不需要任何定时任务）。
   - **CSV 导出**：时间范围 + 本人 / 全家 + 收支类型，字段为「日期 / 记账人 / 收支类型 / 分类 / 备注 / 金额(元) / 记账方式」。
   - 权限：**家庭成员可看全部家庭账单**；但**只能编辑 / 删除自己记的**（别人的账在界面上显示 🔒）；
     分类与推送时间**只有管理员**能改。

升级方式见「十一、版本与升级 → **从 1.9.0 升到 2.0.0**」：
**结构变更全部由程序自动完成**（重建 `todos` 以放开每周约束 + 新建 6 张表），
`docker-compose.yml` 与老 `.env` **原样沿用**（新参数都有默认值，不设也能跑；
想用截图识别再补一个千问（DashScope）API Key，或在网页里填）。

**逐项细节**

1. **图片查看（灯箱）**
   - **双指缩放 1–5 倍**：以**图片中心为锚点**放大（不会往画面外飘）；缩到 1.12 倍以内自动归位。
   - **双击放大 2.5 倍 / 再双击还原**：手机上两次轻击（间隔 < 300ms）、电脑上双击都支持。
   - **滚轮缩放**（电脑）：向上放大、向下缩小，每次 18%。
   - **放大后可拖动平移**：位移被限制在「不把图拖出屏幕」的范围内；光标变成「可拖 / 正在拖」。
   - **左右滑动换图**：位移超过 60px 才算翻页，否则回弹；图片为 1 张时不给位移反馈（滑了也没下一张，给了反而误导）。
   - **平滑过渡**：入场淡入 + 轻微放大到位；换图是从侧方滑入。灯箱用 `visibility` 而非 `display` 切换 —— 这样它在隐藏时**仍然有布局尺寸**，缩放的边界才算得准。
   - **首次打开有 5 秒手势提示**（「双指缩放 / 双击放大」），教完自己淡掉，不长期占画面。
   - 桌面端放大时自动收起左右翻页按钮（它会挡住正在看的图片边缘）。

2. **内容变更提醒的发送时机**
   - **汇总时间（可选）**：留空 = 内容一变更就立刻发（**与旧版本完全一致**）；填了则攒到那个时间点，
     把这一段时间里的变更**合并成一封摘要**发出，家里一天改十几条也不会连收十几封。
   - **免打扰时段（可选）**：例如 `22:00 → 08:00`（**支持跨零点**）。落在时段内的通知顺延到「结束」时刻再发。
   - **不启用的两种写法都安全**：两个都留空、只填一个、起止填成同一时刻 —— 一律按「未启用」处理，
     不会把「00:00 到 00:00」理解成全天静音而把所有通知永久吞掉。
   - **两个设置可叠加**：先按汇总时间取点，再挪出免打扰时段。
   - **可以在「运行状态」页确认**：多了「**发送时机**」与「**待发队列**（待发 N 封 · 下次 HH:MM）」两行 ——
     「设了汇总时间但什么都没发生」时，一眼能看出是还没到点、排队中，还是压根没收到内容。
   - 时间按「家庭设置」里选的**时区**理解，与服务器所在时区无关。

3. **修改登录账号**
   - 入口：「我的 → 账号安全 → **登录账号**」，显示「当前：@xxx」，点右侧「修改」。
   - 需要同时输入**新账号**与**当前密码**（用户名是登录凭据的一半，不能只凭「页面还开着」就改掉）。
   - 规则：**2–20 位，中英文 / 数字 / 下划线**；与他人重名会明确报错；新账号与旧账号相同视为成功。
   - **改完不会把你踢下线**：本机当前会话继续有效，用新账号登录即可；「我的」页与家庭成员列表都会立刻刷新。
   - 管理员也不能绕过 —— 走的是同一个接口、同一套校验。

4. **日历左右滑动切月**
   - 待办日历与「动态日历」共用同一套手势，各记各的月份（互不干扰）。
   - 手指横滑：**左滑 = 下个月，右滑 = 上个月**；位移小于 50px 按误触忽略。
   - **纵向滑动绝不拦截** —— 手机上最容易踩的坑就是「列表滑不动」，所以只有判定为「明确偏横向」时才接管。
   - 切月时日历网格带一个方向明确的滑入动画；顶部仍有「‹ / 今天 / ›」按钮可点。

5. **版块红点（谁更新了）**
   - 规则：某版块里**别人**的最新更新时间 > 我上次查看该版块的时间 → 亮红点。**自己发的内容不给自己亮**（与微信朋友圈一致）。
   - 三个版块各记各的（日历 = 待办、动态、记录本）；**进版块即灭点**（先本地灭、再异步落库，红点不值得打断操作）。
   - 记账在**服务端**（`seen_marks` 表），所以**换手机 / 换浏览器状态一致**，不是本地缓存。
   - 「仅自己可见」的内容不会点亮别人；红点是**纯提示**，取不到就静默跳过，绝不影响主流程。

6. **动态视频 + 点选标签**
   - **视频上传**：发布器「＋ 视频」（可多选，一条动态最多 **3 段**）；编辑弹窗里同样有「＋ 视频」与缩略块上的「×」删除。
   - **格式与体积**：只收浏览器能直接播放的 **MP4 / MOV / WebM**；**按文件头魔数判断，不看扩展名**，
     把 `.avi` 改名成 `.mp4` 也会被当场拒收（收下来只会变成「上传成功却播不了」，比报错更难排查）。
     单段上限默认 **50MB**（`MAX_VIDEO_MB` 可调），超限会明确告诉你「有多大、上限多少」。
   - **播放**：动态里渲染 `<video controls>`，手机上点击即播（`playsinline` 不会强制全屏）。
   - **点选已有标签**：发布器与编辑弹窗里都会列出**已经用过的标签**，点一下即追加进标签输入框（不用手打、不会拼错）；
     去重，已存在的标签不会重复加。

7. **记录本长按归档**
   - 手势与「长按删除分类」共用一套：手机上按住 **0.5 秒**，电脑上**右键**。
   - 顶部有「**当前记录 / 已归档**」两个视图；归档后的卡片在「已归档」里显示，并带「🗄️ 已归档」标记、整体弱化显示。
   - 确认框里写明**这只是收起来**：记录仍在库里、**搜索照样能搜到**、附件与图片一张不少。
   - 随时可以再长按 / 右键一次**取消归档**；归档只是把 `records.archived` 置位，不改内容、不改可见性。

8. **按月重复（公历 / 农历）**
   - 待办表单的「重复」现在是五选一：不重复 / 每年公历 / 每年农历 / **每月公历** / **每月农历**。
   - **每月公历**：每月同一天；遇到小月**顺延到当月最后一天**（例如每月 31 号 → 2 月按 28 号，闰年按 29 号）。
   - **每月农历**：按农历日；遇到**没有这一天的小月就跳过该月**（例如「每月三十」，二月只有二十九天时当月不提醒），不会硬凑到别的日子。
   - **与「提前 N 天」叠加正常工作**：提前提醒后的日期若跨到上一个月，仍然正确判定为「本月那一次」。
   - 按月重复和年度重复一样**没有完成状态**（不再出现「这个月的房租已完成」这种自相矛盾的记录）。
   - 与旧版本的年度规则、农历算法**完全共用同一份实现**（`public/repeat.js`，前后端同一文件），不会出现「日历上看得到、提醒却不发」。

9. **动态共创（一起写）**
   - 入口：动态卡片右上角的「**✍️ 一起写**」。
   - 可追加**文字（≤2000 字）、图片（≤9 张）、视频（≤3 段）**，至少要有一样；保存后**立刻显示在这条动态下方**。
   - **留痕**：每条补充都带「谁加的 + 一起写 · 什么时候」；卡片上显示「✍️ 一起写（N）」。
   - **权限**：只有「全家可见」的动态能共创 ——「仅自己可见」的动态作者自己可以补，别人**取不到**（返回 404，不泄露是否存在）。
   - **撤回**：补充者本人可以删掉自己补的内容；**动态作者也能清理自己动态下的任何一条**（与评论的删除规则一致）。
   - 有人「一起写」会**更新这条动态的更新时间** → 动态流排序与红点提示都能注意到它；也会触发内容变更通知。

10. **动态按日历查看**
    - 动态页顶部可在「**动态流** / **按日历看**」之间切换（切换不影响已输入的内容）。
    - 日历格**右上角显示当天动态条数**（角标），当天被选中时角标高亮；跨月的那几格弱化显示。
    - **点某一天** → 下方列出那天**全部动态**（按时间倒序，带作者头像与时间），显示「N 条动态」；没有就是 0 条。
    - 与待办日历一样**支持左右滑动切月**，并有「‹ / 今天 / ›」按钮。
    - 归日按**浏览器本地时区**（你在哪儿看，就是哪天的动态）。

升级方式见「十一、版本与升级 → 从 1.8.0 升到 1.9.0」：**唯一的结构变更会由程序自动完成**（重建 `todos` 以放开重复规则的校验约束 + 建两张新表 + 补两列），
`docker-compose.yml` 与老 `.env` 原样沿用（新参数 `MAX_VIDEO_MB` 有默认值，不设也能跑）。

## 更早版本（v1.7.0）

1. **修掉手机端待办「字体重叠」** —— 根因找到了：条目高度固定 68px，内部三行又是**可压缩**的
   弹性子项；手机上「📅 日期 / 🕐 时间 / 👥 参与人」这一行放不下会折成两行，三行总高超出可用高度时，

2. **动态列表更紧凑** —— 两条动态之间的间距由 22px 收到 **8px**（原来列表间距与卡片外边距叠加了两层）。

   想看全文点进查看页，内容一字不少。
4. **记录本访问密码更好用** —— 解锁时**访问密码与登录密码任一都可以**

   可人明明已经登录进来了）。「记录本访问密码」弹窗现在**既能改也能关**：
   改密码只需填一次「原访问密码**或**登录密码」，再选改成自定义密码还是回头复用登录密码。
5. **家庭设置里的「运行状态」精简 + 5 个页签等高** —— 运行状态把「开关」与「发件配置」并成一行、
   扫描时间与扫描条数并成一行、按钮旁的长说明缩成一句话，整块高度约为原来的三分之二；

5. **待办时间设置大幅简化** —— 原来是「点开开始时间表盘 → 点开结束时间表盘」两步。
   现在改成**点一个常用时间（早 8:00 / 上午 9:00 / 中午 12:00 / 下午 3:00 / 晚上 7:00）+
   挑一个时长（30 分钟 / 1 小时 / 1.5 小时 / 2 小时 / 3 小时 / 不限）**，
   结束时间自动算出来；需要精确时间时选「自定义…」才展开结束时间输入框。
   表单里会实时显示「将记录为 15:00 – 16:00」，提交前就知道会存成什么。
6. **自定义头像** —— 「我的」页点自己的头像即可上传照片，**自动按中心裁成方形并压缩**（不用自己先处理）。
   头像会出现在「我的」、动态与评论里；图片缺失或加载失败时自动回退到「昵称首字色块」，
   也可以一键「恢复默认」。
7. **记录本分类支持长按删除** —— 长按分类标签（手机上长按 0.5 秒 / 电脑上右键）即可删掉这个分类。
   **该分类下的记录不会被删除，而是移到「通用」**（确认框里写明了这一点）；
   删掉的分类会进入隐藏名单，家人打开都看不到它，不会被自动重建回来。
   「全部」与「通用」不可删除。
8. **动态页搜索框重做** —— 搜索框做成一体化搜索条（放大镜图标 + 圆角输入 + 出现关键词时才显示的一键清除），
   并与标签筛选并入同一张卡片，整块看起来是一个整体，不再是两个各自为政的小方块。

升级方式见「十一、版本与升级 → 从 1.5.0 升到 1.6.0」：**只补一列数据库字段（`users.avatar`），
`docker-compose.yml` 与老 `.env` 直接沿用**。

  - **草稿不会因收起而丢**：收起再展开、或者中途刷新，已经打的字与选的标签都还在，
    按钮上还会带一个小角标显示「有几张图 / 有没有文字」（如「✍️ 发帖 1」）

  - **点图片再点一下就正常关闭（v2.0.0 修复）**：以前点开大图后再单击，会出现「关不掉 / 闪一下又弹回来」。

    指针下面已经是灯箱底下那张缩略图，于是「关闭」的那一下顺手又把灯箱打开了。

    左右切换与 ✕ 按钮不参与这套判定。行为总结：**单击图片 / 点空白 → 关闭；双击 → 放大或还原**

- **图片长按（手机）/ 右键（电脑）弹出菜单**：查看大图、保存图片到本地

  - **点选已有标签（v1.9.0）**：发布器与编辑弹窗里都会列出**用过的标签**，点一下即加入（不用手打、不会拼错），自动去重

  - **可自定义头像（v1.6.0）**：每位成员都能在「我的」页点自己的头像上传照片，

    「昵称首字 + 按名字生成的底色」，也可以一键「恢复默认」

```

│  server.js        静态资源 · 路由 · Cookie · 会话中间件    │
│  src/auth.js      注册 · 登录 · 会话滑动续期 · scrypt 密码 │
│  src/api.js       业务接口（可见性判断唯一收口点）         │

│  src/userprefs.js 个人通知偏好（每人一份，只能收窄）       │
│  src/billparse.js 一句话记账解析（金额/方向/日期/分类）    │
│  src/ocr.js       千问截图识别 + 月度护栏（前端零密钥）    │
│  src/bills.js     家庭记账：明细/统计/日报/导出/定时       │
├────────────────────────────────────────────────────────────┤
│  data/family.db   ← 全部结构化数据（单文件）               │
│  data/uploads/    ← 图片文件                               │
└────────────────────────────────────────────────────────────┘
```

> **`public/repeat.js` 是重复规则的唯一实现**（每周公历，每月公历/农历，每年公历/农历），
> 前端万年历与服务端提醒调度都 `require` 同一个文件
> （UMD 写法，浏览器挂 `window`、Node 挂 `module.exports`）。这一点很关键：两边各写一份的话，
> 迟早会出现「日历上算出来的日子」和「提醒算出来的日子」不一致，表现为提醒莫名不发。
> **v2.0.0 加「每周」时也只改了这一处**，前端下拉项与服务端提醒自动同步扩张。

**技术选型与理由**

| 选择 | 理由 |
|---|---|
| SQLite 单文件库 | 零运维；备份 = 拷一个文件；迁移 = 拷一个目录 |
| Node 内置 `node:sqlite` | Node ≥ 22.5 自带，服务器上不需要编译任何原生模块 |
| 原生 `node:http` | 不引框架，`npm install` 都可以跳过，部署路径最短 |
| httpOnly Cookie 会话 | token 不进 localStorage，天然防 XSS 窃取；也不受任何第三方平台域名限制 |
| 前端零构建 | 4 个静态文件，不需要 Node 构建链 |
| 轮询同步（12 秒） | 家庭级并发下最简单可靠；无长连接、无额外依赖 |

## 四、数据模型

| 表 | 用途 | 主要字段 |
|---|---|---|
| `users` | 家庭成员 | `username`、`display_name`、`password_hash`(scrypt)、`is_admin`、`notify_email`、`avatar`(v1.6.0，空串 = 昵称首字色块)、`record_lock_enabled`/`record_lock_hash`(记录本访问密码) |
| `sessions` | 登录会话 | `token`、`user_id`、`expires_at`、`last_seen_at`、`records_unlocked_key`(页面级记录本解锁凭证) |
| `todos` | 待办事项 | `title`、`todo_date`(可空)、`start_time`、`end_time`、`location`、`participants`(JSON)、`priority`、`repeat`(v1.9.0 起含 `solar_monthly`/`lunar_monthly`，**v2.0.0 起含 `solar_weekly`**)、`done`、`remind`、`reminded_at`、`remind_key`、`visibility` |
| `posts` | 图文动态 | `content`、`images`(JSON)、`tags`(JSON)、`videos`(JSON，v1.9.0，最多 3 段)、`visibility` |
| `comments` | 动态评论 | `post_id`、`content`（随动态级联删除）；**没有 visibility 列**，可见性跟随所属动态 |
| `post_contribs` | 动态共创「一起写」（v1.9.0） | `post_id`、`user_id`、`owner_name`、`content`、`images`(JSON)、`videos`(JSON)；**没有 visibility 列**，可见性跟随所属动态 |
| `records` | 重点事项 | `title`、`content`、`category`、`tags`(JSON，界面已停用但数据保留)、`images`(JSON)、`attachments`(JSON，v1.5.0)、`archived`(v1.9.0 归档标记)、`pinned`、`visibility` |
| `seen_marks` | 版块已读时间（v1.9.0 红点） | `user_id` + `kind`(`todo`/`post`/`record`) 唯一键、`seen_at`；与各版块最新更新时间比较决定是否亮红点 |
| `user_prefs` | 个人通知偏好（v2.0.0） | `user_id` + `key` 唯一键、`value`。当前键：`remind_enabled` / `notify_on_change`（三态开关）、`remind_quiet_start`/`remind_quiet_end`、`notify_quiet_start`/`notify_quiet_end`（个人免打扰）、`notify_kinds`（个人接收类型，`none` = 全不要）。**哪一行不存在 = 跟随管理员全局设置**，所以旧用户升级后行为零变化 |
| `bills` | 家庭账单流水（v2.0.0） | `user_id`、`owner_name`、`kind`(`income`/`expense`)、`amount_cents`(**金额存「分」整数**，避免浮点误差)、`category`(分类名快照)、`note`、`source`(`text`/`ocr`)、`raw`(原话 / OCR 原文，可追溯)、`spent_on`(算在哪一天，与 `created_at` 分开)；**没有 visibility 列**，账单本身就是全家共享 |
| `bill_categories` | 收支分类（v2.0.0） | `kind` + `name` 唯一、`sort`；出厂预置支出 12 类 / 收入 7 类，管理员可增删 |
| `bill_budgets` | 分类月度预算（v2.0.0） | `category`(主键)、`amount_cents`；记账后若该分类当月已达预算，在聊天窗里提醒一句。**只对支出分类有意义**（v2.0.1 起界面不再给收入分类渲染预算输入框，服务端 `setBudget` 也会拒绝收入分类） |
| `bill_chat` | 记账聊天记录（v2.0.0） | `user_id`、`role`(`user`/`system`)、`text`、`bill_id`、`created_at`；**每人一份**，只保留最近一段（`CHAT_KEEP`），不做无限增长 |
| `ocr_usage` | OCR 月度用量（v2.0.0） | `month`(主键，`YYYY-MM`)、`used`。**主键是月份字符串 → 跨月清零不需要任何定时任务** |
| `settings` | 系统设置 | `key`/`value` 键值对：注册开关、免登录时长、提醒时间与提前天数、SMTP、通知开关与类型、**内容通知的发送时机（v1.9.0：`notify_digest_time` / `notify_quiet_start` / `notify_quiet_end`，空串 = 立即发 / 不启用免打扰）**、记录本隐藏分类（v1.6.0）、**站点名称 `site_name`（v1.8.0，留空 = 默认名）**、**记账相关（v2.0.0：`bill_reports_enabled` / `bill_monthly_report` / `bill_daily_time` / `bill_ocr_ak` / `bill_ocr_sk`）**。以上都是这张表里的**键**，**不是新建的表或列**，所以加它们不需要任何迁移；旧库里残留的 `family_name` 保留但永不读取 |

四张业务表（`todos` / `posts` / `records` / `bills`）都带 `user_id`（创建者）与 `owner_name`（创建者昵称快照，仅用于显示，不参与权限判断）。
`comments`、`post_contribs` 与 `bills` 没有 `visibility` 列 —— 前两者的可见性**跟随所属动态**（误套可见性谓词会直接 500），
`bills` 则是**设计上就是全家共享**（需求明确「家庭成员可查看全部家庭账单」）。

`visibility` 只有两个取值：`family`（默认，全家可见）与 `private`（仅创建者可见）。

**结构性迁移只有一处（v2.0.0）**：`todos.repeat` 的 `CHECK` 约束要放开 `solar_weekly`。
SQLite 不支持修改约束，所以只能「**建新表 → 逐列拷贝 → DROP → RENAME**」重建一次。
重建时 `remind` / `reminded_at` / `remind_key` 三个提醒相关列都会原样搬过去
（`remind_key` 缺失会导致年度重复的「已提醒」状态丢失、第二天重复轰炸）。
其余 6 张新增表（`user_prefs` / `bills` / `bill_categories` / `bill_budgets` / `bill_chat` / `ocr_usage`）
都是 `CREATE TABLE IF NOT EXISTS`，**老库直接补齐、已有数据一行不动**。

建表语句全部是 `CREATE TABLE IF NOT EXISTS`，服务每次启动自动执行，升级版本不会丢数据。

## 五、权限控制方式

**两道闸门 + 一条可见性规则，全部在服务端强制执行，前端只负责界面提示。**

```
第一道：会话中间件   →  /api/* 全部要求已登录（只有配置、注册、登录三个接口公开）
第二道：可见性收口   →  所有数据读写都经过同一个可见性谓词
```

**可见性规则（唯一实现处：`src/api.js` 的 `VISIBLE` 常量）**

```sql
可见  ⟺  visibility = 'family' OR user_id = <当前登录用户>
```

| 内容 | 谁能看到 | 谁能改 / 删 |
|---|---|---|
| `visibility = 'family'`（默认） | 全部家庭成员 | **全部家庭成员**（协作式，家人可以帮你改日程、勾完成） |
| `visibility = 'private'` | 仅创建者本人 | 仅创建者本人 |
| 家庭账单 `bills`（v2.0.0） | **全部家庭成员**（账单没有 `visibility`，设计上就是家庭共享） | **仅创建者本人**（别人的账单在界面上带 🔒，接口层同样按 `user_id` 再拦一次） |
| 个人通知偏好 `user_prefs`（v2.0.0） | 仅本人 | 仅本人（接口从会话取 `user_id`，改不了别人的） |
| 记账设置、分类管理、推送时间（v2.0.0） | 全部成员可看 | **仅管理员**（非管理员提交返回 `403`） |

> 「个人设置只能收窄」也是权限的一部分：**家里关掉的类型，个人勾上了也收不到** ——
> 个人偏好永远无法越权放大全局设置，管理员的总闸依然有效。

**防伪造与防绕过**

- 写入时 `user_id` **一律取自服务端会话**，客户端传了也会被忽略（有专门测试覆盖）
- 修改/删除前先按可见性取一次记录，取不到就返回 `404`（不泄露「这条记录是否存在」）
- **可见性开关只能由创建者修改**，避免他人把别人的家庭内容「藏起来」（返回 `403`）
- 所有 SQL 参数绑定，无字符串拼接，防注入
- 所有用户输入在渲染时做 HTML 转义，防 XSS
- 图片文件名由服务端生成，不使用客户端传来的文件名；校验 MIME 类型与体积，防目录穿越与非图片上传
- 不开放 CORS；静态资源带 CSP、`X-Content-Type-Options: nosniff` 等安全头
- 密码用 `scrypt` + 16 字节随机盐哈希，校验用恒定时间比较；登录失败信息不区分「用户不存在 / 密码错误」

> ⚠️ 二次开发注意：新增涉及 `todos / posts / comments / records` 的接口时，
> **必须**沿用 `VISIBLE` 谓词，否则等于开了越权漏洞。

## 六、数据同步方案

**服务端 SQLite 是唯一数据源（single source of truth），客户端不做权威副本。**

### 写入：乐观更新 + 回读校验
1. 点击后界面**立即**更新（不等网络往返，保证操作跟手）
2. 发起写请求
3. 服务端返回写入后的真实行 → 以服务端结果为准覆盖本地
4. 失败（网络错误 / 权限拒绝 / 校验不通过）→ **回滚界面**并提示原因，绝不假装成功

### 读取：轮询 + 事件触发
- 每 **12 秒** 轮询一次，且**只刷新当前打开的板块**，省流量省电
- 以下时机立即刷新：切回页面（`visibilitychange`）、窗口重新聚焦（`focus`）、网络恢复（`online`）
- 顶部有手动刷新按钮与同步状态指示（已同步 + 时间 / 同步中 / 离线）

### 多人协同效果
任一成员在日历上新增或修改待办，其他成员最长 12 秒内看到；勾选完成、发表评论同理。
评论采用「取回动态时一并取回其全部评论」的方式，避免逐条请求，也保证评论不会漏显示。

### 失效兜底
网络异常时界面保留最后一次同步的只读内容，顶部显示「离线」；恢复后自动补齐。
本地缓存**只用于展示**，任何写入都以服务端为准。

### 输入不被打断（v2.0.0 起做到「一个字节都不动」）
轮询刷新会重绘界面，因此刷新被设计成**最小重绘**，而不是把整页 HTML 重来一遍：

1. **数据指纹先行**：每次刷新先算当前版块的数据指纹，与上次**完全一致就直接返回**，
   连一个 DOM 节点都不碰 —— 大多数轮询都属于这一种（12 秒一次、家里没有别人在改东西时）。
2. **数据变了才做 diff**：按 `patchHtml → patchChildren → patchNode` 逐层比对，
   **只改真正变了的那几个节点**，其余节点的 DOM 引用保持不变。
   这一点直接决定了**正在播放的视频不会被重新加载**（视频元素没被替换，播放不中断）。
3. **焦点所在的那一个节点直接跳过**：`patchNode` 里判断焦点是否**正好**落在这个节点上，
   是就跳过它（`if (holdsFocus(oldNode)) return;`）。
   - ★ **v2.0.1 收窄过这里的粒度**：原来是「焦点在这棵子树里就整棵跳过」，
     结果输入框所在的那张卡片（连同卡片里的新消息、新评论、被删掉的行）全被冻结 ——
     表现为「删了还在」「发了没回显」「评论不及时」。现在只跳焦点那一个节点：
     输入控件自己受保护（`value` / `checked` 是 DOM 属性，重建才会丢），兄弟内容照常更新。
4. **输入内容双重保险**：带 `data-preserve` 键的输入框会在重绘前 `captureInputs()`、
   重绘后 `restoreInputs()`，输入内容与光标位置都恢复。
5. **搜索框等派生展示态就地同步**：「有没有关键词」派生的样式（放大镜状态、清除按钮显隐）
   在**改关键词的地方** `syncSearchBar()` 立刻同步一次 —— 不能只靠渲染同步，
   因为上一条「跳过聚焦节点」会把渲染挡掉。
   「清除」按钮也改为**常驻 DOM、用 `hidden` 控制显隐**（只靠「有词才渲染」与最小重绘相撞会自相矛盾）。

一句话：轮询照旧，但**正在打的字不会丢、正在放的视频不会断、光标不会跳**。

## 七、备份与迁移

### 三种备份方式

| 方式 | 做法 | 适合 |
|---|---|---|
| **App 内一键导出** | 「我的 → 导出备份」下载一个 JSON（含全部数据 + 图片 base64） | 日常随手备份，可跨机器恢复 |
| **服务器冷备份** | `npm run backup` → 产出 `data/backups/family-hub-<时间>.db` | 定时任务，恢复最快 |
| **整目录拷贝** | 直接 `cp -r data/ 别处` | 迁移前的一次性快照 |

冷备份用的是 SQLite 的 `VACUUM INTO`，会自动包含 WAL 中尚未落盘的数据，**不需要停服务**，产出的是一致性快照。

### Docker 部署时的备份

数据是**绑定挂载**到宿主机 `./data` 的（不是命名卷），所以备份方式完全一样，甚至不用进容器：

```bash
docker compose exec app node scripts/backup.js   # 冷备份 → 产物落在宿主机 ./data/backups/
ls -lh data/backups/                             # 直接在宿主机看
tar czf /backup/family-hub-$(date +%F).tar.gz ./data   # 含图片的整目录快照
```

`docker compose down` 不会删除 `./data`，迁移时把这个目录拷到新机器即可（Docker 与源码两种部署方式之间也能互相迁移）。

### 恢复

- **从 App 备份恢复**：「我的 → 从备份恢复」选择 JSON 文件。整体替换现有数据，不可撤销，仅管理员可执行，恢复后需重新登录。
- **从冷备份恢复**：停止服务 → 用备份文件覆盖 `DB_PATH` 指向的文件（同时删掉同目录的 `-wal` / `-shm` 文件）→ 重启。

### 迁移到新服务器

```bash
# 1. 旧服务器：打包代码与数据
tar czf family-hub.tar.gz family-hub/          # 若 data 很大，可只打代码 + 单独拷 data

# 2. 新服务器：装 Node ≥ 22.5，解包，启动
tar xzf family-hub.tar.gz && cd family-hub
node server.js
```

只要 `data/` 目录跟着走，历史数据、图片、密码全都在。**不需要任何数据库导入导出工具。**

## 九、配置项

所有配置都可以通过环境变量或项目根目录的 `.env` 文件设置（参考 `.env.example`）。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3455` | 服务端口 |
| `HOST` | `0.0.0.0` | 监听地址；只给本机访问可设 `127.0.0.1` |
| `DB_PATH` | `data/family.db` | SQLite 文件路径 |
| `UPLOAD_DIR` | `data/uploads` | 图片与记录本附件的存放目录 |

## 十、已知边界

- **单家庭模式**：能拿到网址并注册的人都属于同一个家庭，能看见全部家庭内容。若需要严格隔离（多个独立家庭共用一个部署），在数据层加一个 `family_key` 字段并用邀请码加入即可，改动集中在 `src/schema.sql` 与 `src/api.js` 的可见性谓词。
- **轮询同步最长 12 秒延迟**，不是 WebSocket 实时推送。家庭场景足够；如需秒级实时可加 SSE。
- **登录方式为用户名 + 密码**，不含邮箱验证码与第三方登录（因此也不依赖任何外部服务）。忘记密码由管理员重置。
- **图片在前端压缩后上传**（最长边 1600px、JPEG 0.82），原图不保留。GIF 不压缩以保留动画。
- **视频只收浏览器能直接播的三种容器**（MP4 / MOV / WebM，v1.9.0），AVI / MKV / WMV 会被明确拒收而不是「传上去播不了」；视频**不在前端转码**（浏览器里转码既慢又不可靠），所以体积与格式由源头决定。单段默认 50MB、一条动态最多 3 段。
- **版块红点是「拉」不是「推」**（v1.9.0）：它跟随 12 秒的轮询节奏更新，不是毫秒级实时；判断依据是「别人在这个版块里的最新更新时间」，所以自己改自己的内容不会点亮自己。
- **记账的 AI 依赖外部服务（v3.0.0；v4.2.0 起范围收窄到「只有截图识别」）**：截图识别调阿里云千问的公开接口，**离线/内网环境不可用** ——
  此时「传小票」会明确报错，但**一句话记账（纯本地解析）与其它功能完全不受影响**（AI 是可选的锦上添花）。
  本地月度护栏默认**每月 1000 次**（管理员可改），用满后到月底都不可用（下月 1 号自动归零，无需人工干预）。
- **一句话记账是纯本地规则匹配（v2.0.0 起，v4.2.0 起不再有任何 AI 分支）**：它靠关键词与正则理解「金额 / 收支方向 / 日期 / 分类」，
  所以**没听清的句子会被明确拒绝**而不是猜一个数字；也不会因为没配千问 / 断网 / 超额度的任何原因而失效。
  写法越接近 `买菜 30 元` 越准；金额一律按「分」入库，界面上按两位小数显示。
- **记账没有「多退少补」式的账户概念（v2.0.0）**：只记「一笔收支」，不维护银行卡/钱包余额，
  也不做账户间转账。想要余额对账可以把导出的 CSV 拿去 Excel 里做。
- **个人通知偏好只能收窄（v2.0.0）**：个人无法开启「管理员已经整体关掉」的通知类型，
  也无法修改提醒时间点、提前天数、发件邮箱这些**全局**参数 —— 这是刻意设计的边界。
- **单进程单文件库**，适合家庭级并发（几十人以内）。若要做多实例负载均衡，需要把存储换成 PostgreSQL —— 数据访问都集中在 `src/db.js`，替换点很清晰。
- 网页端不支持手机号 / 微信一键登录；若要这类登录方式需改做微信小程序。

### 图片上传失败的两个真实原因（v1.5.0 已修复）

排查时用真实负载打接口，定位到两条原因，都不是「网络不好」：

**原因一：旧的大小上限（5MB）比手机原图还小。**
手机拍一张照片常在 5-8MB。旧版本前端会把图片压缩后再传，但当**浏览器解不开这张图**时，
代码会**静默回退成「不压缩、原样上传」**，于是 5.5MB 的原图撞上 5MB 上限被拒，
而界面上只显示一句没有细节的失败提示 —— 用户完全不知道发生了什么。

修法（两端协同）：
- 客户端：逐级降质压缩（最长边 1600px@0.82 → 1280@0.70 → 1024@0.60）；
  **实在解不开时不再偷偷传原图**，而是明确告诉你「是哪一张、为什么、怎么办」并跳过这一张，
  其余图片照常上传（不会因为一张坏图导致整批失败）
- 客户端按服务端下发的上限**在本地就拦住并报出真实大小**，不必等几 MB 传完再被拒
- 服务端：图片上限 **5MB → 10MB**（`MAX_UPLOAD_MB`），并把「实际多大 / 上限多少」写进错误信息
- 请求体上限按 `max(图片上限, 附件上限, 视频上限) × 1.4 + 4` 推导（默认即 74MB），
  避免出现「文件没超限却被 413 挡住」；v1.9.0 加了视频通道后这一条同样适用

**原因二：不认 iPhone 的 HEIC 与部分格式。**
旧版本用一张**写死的类型白名单**校验，只认 JPG / PNG / WEBP / GIF，于是 HEIC（iPhone 默认格式）、
AVIF、BMP、TIFF 全被拒；而且校验的是**客户端声明的 MIME**，安卓浏览器有时会把它写成 `image/heic`
（哪怕文件其实是 JPEG），结果**明明是 JPG 也被拒**。

修法：改成**读文件头（魔数）判断真实类型**，不再相信客户端声明的 MIME：
- JPEG / PNG / GIF / WEBP / BMP / TIFF / AVIF / ICO 按真实字节识别后正常收下
- **HEIC 会给出一句能照做的提示**（iPhone 设置 → 相机 → 格式 → 兼容性最佳，可在相册导出为 JPG）
- **SVG 明确拒收**（可内嵌脚本，属于 XSS 风险），并说明改用 JPG / PNG
- 谎报 MIME 的 JPEG 现在能正常上传（诊断脚本里专门有一项）

复现与验证工具：`_verify/diag-upload.js` 会用真实文件头构造各类型/各体积的负载打真实接口，
逐项打印「预期 / 实际」，可随时重跑对照。

## 十一、版本与升级

当前版本 **4.3.0**。版本号唯一来源是 `package.json`，启动时通过 `/api/config` 下发，
页面底部与容器标签用的都是它（`Dockerfile` 的 `APP_VERSION`、`docker-compose.yml` 的 `image` 标签同步）。

### 从 4.2.0 升到 4.3.0

**零结构变更 + 零新增环境变量** —— 不新增表、不新增列，也不需要动 `.env` 或 `docker-compose.yml`，
`migrate()` 无事可做，`docker compose up -d --build` 即完成（离线部署换 `family-hub-4.3.0.tar`）。
新增配置项（思考模式 / 输出上限 / 温度 / 超时 / 重试 / 自愈 / 分类模式 / 图片压缩）**全部存在 `settings` 表**，
